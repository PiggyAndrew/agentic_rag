# Word 仿写与同格式导出（doc/docx）后端方案记录

## 目标

实现一个后端能力：用户提供参考 Word 文档（doc 或 docx），并输入“要写的内容/要求”（纯文字或文字 + 参考文档），系统输出一个新的 docx：

- 尽可能复用参考文档的格式与版式（段间距、字号、字体、缩进等）
- 内容与写作风格由 AI 基于参考文档进行仿写
- 输出为可下载的 Word 文档

## 可行性结论

- 推荐路线：以参考 docx 作为模板，尽量不改模板样式，仅替换文本内容，可获得最高的格式一致性。
- doc（旧版二进制）建议服务端先转换为 docx，再走同一套模板替换流程。
- “格式完全一致”需要明确范围：段落级格式可高保真；复杂对象（页眉页脚、目录域、多级编号、文本框、复杂表格、修订/批注等）需要分阶段支持。

## 现状对接点（基于当前后端）

- HTTP 框架为 FastAPI，路由集中注册于 backend/api/main.py。
- 现有体系已经具备：
  - 通过 API 上传文件并保存到磁盘（data/kb/.../uploads）
  - 通过 LLM（DeepSeek/OpenAI 兼容接口、Ollama）生成内容

## 分层方案

### MVP（首选上线形态）：模板替换（段落级保真）

目标：参考 docx 的段落结构与段落样式保持不变，仅替换每段文本，输出 docx。

流程：

1. 输入
   - reference_file：docx（必选）
   - instruction_text：用户要写什么、约束是什么（必选）
   - 可选：输出长度、语言、主题词、保留/替换哪些段落范围
2. 模板解析
   - 读取 docx 段落序列，抽取：段落索引、段落样式名、段落属性（对齐、缩进、行距、段前后）、段落类别（标题/正文/空行/列表）
   - 统计每段原始字数，作为生成时的“目标长度”约束
3. 风格画像（LLM）
   - 取模板的正文样本文本（如前 N 段 + 典型段落），让 LLM 生成结构化风格参数：语气、句长、术语密度、段落组织、常用连接词等
4. 内容生成（LLM）
   - 让 LLM 严格按段落结构输出 JSON：[{paragraph_index, text}]，并为每段提供字数范围约束
   - 生成策略：先写大纲/要点，再按段落填充，降低跑题与段落错位风险
5. 渲染输出
   - 以模板 docx 为基础生成新文档
   - 遍历段落，将段落文本替换为生成文本，尽量不修改段落属性
6. 交付
   - 返回生成 docx 文件流，或落盘并返回下载地址

建议依赖：python-docx

### V1：支持 doc 输入 + 更强风格一致性

新增能力：

- doc → docx 转换
  - 服务端通过 LibreOffice headless 或等价转换服务完成
  - 转换后进入 MVP 流程
- 风格一致性增强
  - 风格画像更结构化，并在生成阶段强约束：段落句数、每句字数、术语表、常用句式
  - 可选：建立“术语/专有名词”抽取与回填机制

### V2：高保真（复杂对象与 run 级格式）

仅在强需求时推进：

- run 级混合格式保留（同段内加粗/颜色/链接/上下标等）
- 多级编号与列表结构保留
- 表格按 cell 结构替换文本
- 页眉页脚、目录域与自动编号等高级对象

## API 设计建议

### 同步接口（适合小文档、快速体验）

- POST /api/docx/rewrite
  - multipart/form-data
    - reference_file：上传 doc/docx
    - instruction_text：用户输入
    - mode：mvp/v1/v2（默认 mvp）
  - 返回：docx 文件流（content-type 为 docx）

### 异步接口（适合大文档、避免超时）

- POST /api/docx/rewrite/tasks
  - 返回 task_id
- GET /api/docx/rewrite/tasks/{task_id}
  - 返回状态与下载链接

## 质量与验收口径（建议首版）

- 覆盖：标题/正文段落、段前后/行距、缩进、对齐方式、默认字体字号
- 不保证：页眉页脚、目录域、自动编号、多栏、文本框、复杂表格、批注与修订
- 文本结构：段落数量与标题层级与模板一致
- 长度控制：每段字数在模板原字数的 ±30%（可配置）

## 风险与控制

- 长文导致分页变化：通过段落目标字数约束、段落句数约束降低偏差
- LLM 可能跑题：通过“先结构化输出 JSON、再逐段生成”的两阶段方式降低
- 复杂格式支持成本高：按 MVP → V1 → V2 分层推进，避免一次性全做
